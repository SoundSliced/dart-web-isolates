Regression shapes (patched, fresh fixture per case)
---------------------------------------------------
- asset-only hook dependency (writes a file, emits no Dart source): build exit
  0, hook ran exactly once, no hook asset appeared in build/web (same on the
  unmodified SDK), no extra hook execution. This fixture does not declare a
  hooks-API DataAsset, so asset BUNDLING for a declared data asset is still
  unmeasured.
- two hook dependencies (distinct markers): exit 0, both hooks ran once, both
  markers written, build_hooks Complete before dart2js Starting.
- one of two hooks throws: exit 1, "Target build_hooks failed", dart2js never
  started (0 occurrences of "dart2js: Starting"), build/web has no
  main.dart.js (only canvaskit/, flutter.js, flutter_bootstrap.js, index.html).
- single failing hook: same shape — exit 1, "Bad state: hook boom",
  "Target build_hooks failed: ... Building native assets failed", no compiler.
- no-hook app: patched cold 17 s / unchanged 14 s; unmodified cold 18 s /
  unchanged 14 s; both exit 0. Unchanged build logs "Skipping target:
  build_hooks" and "Skipping target: dart2js".
- unchanged build with a hook: first build runs the hook once, second build
  skips build_hooks entirely (invocation counter unchanged at 1).
- dwi.yaml lifecycle (target js -> wasm -> js -> deleted -> absent):
  every build exit 0; JS worker present in all five; the Wasm bundle appears
  when target: wasm and is RETAINED after switching back to js and after
  deleting the file (stale artefacts are not deleted). The hook runs on every
  build while dwi.yaml is absent (missing optional file is a dirty input) and
  is skipped on an identical rebuild once dwi.yaml is stable.

Method notes (do not read these rows as more than they are)
-----------------------------------------------------------
- Browser execution only checks packaging and URLs. Compiler-to-hook ordering
  is proven by the build tests and the verbose traces above, not by a browser.
- Patched build times are cold builds of a fresh app; the unmodified numbers
  stop at the compile error, so they are not a like-for-like comparison.
