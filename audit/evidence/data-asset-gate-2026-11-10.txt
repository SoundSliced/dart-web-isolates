Dependency-hook DataAsset gate — measured on 3.47.9, unmodified vs patched
Date: 2026-11-10
Recorded by: DWI milestone work (handoff "finish the Flutter web-hook prototype evidence")
Status: prototype evidence. NOT an accepted Flutter design, NOT in any released SDK.

Question
--------
Does a DEPENDENCY package's web build hook that declares a `DataAsset` through
the hooks API still build, and still bundle that asset, when the patched SDK
makes `Dart2WebTarget` wait for `BuildHooks(platform: web)`?

Environment
-----------
OS:          macOS 26.5.1 (25F80), arm64
Unmodified:  .research/flutter-sdk         — Flutter 3.47.9, framework
             c197ca5199e, engine 89c39edfdfae (hash 9e025265bef3), Dart 3.13.7
Patched:     .research/flutter-sdk-patched — same revisions + the hook-ordering
             patch (targets/web.dart plus its two tests), own tool snapshot
Feature:     Dart data assets are OFF by default on 3.47.x. Both SDKs were run
             with `enable-dart-data-assets` and `enable-native-assets` enabled
             in an isolated HOME; the real user config was not modified.
Pub cache:   fresh writable cache (the shared hosted cache is read-only here)
Reference:   constructed from Flutter's own fixtures
             packages/flutter_tools/test/integration.shard/isolated/
             dart_data_asset_utils.dart and dart_data_asset_flutter_build_test.dart,
             and dev/integration_tests/data_asset_package (a dependency hook
             that declares data assets — the shape this gate needs).

Fixture
-------
Committed at tooling/data_asset_gate: a scratch app path-depends on
`data_asset_gate_package`, whose hook/build.dart declares, via
`output.assets.data.add(DataAsset(...))`:

  data/id1.txt        declared asset, content controlled by the gate
  data/generated.txt  generated by the hook itself

The hook also increments a `.hook_runs` counter so "ran again" can be told from
"skipped" without reading logs. Everything is independent of DWI.

Results — identical on both SDKs
--------------------------------
                                  unmodified 3.47.9        patched 3.47.9
  first build                     exit 0, hook runs 1      exit 0, hook runs 1
  id1.txt in build/web            packages/data_asset_gate_package/data/id1.txt
                                  content "package_content1" on both
  generated.txt                   present, "generated_content1" on both
  unchanged rebuild               exit 0, hook runs 1 -> 1 (SKIPPED), asset kept
                                  (log: "Skipping target: build_hooks")
  changed input (content2)        exit 0, hook runs 1 -> 2, bundled content
                                  "package_content2" on both
  removed input (file deleted)    exit 1, "Target build_hooks failed",
                                  dart2js never started, on both
  throwing hook                   exit 1, "Bad state: data asset hook boom",
                                  "Target build_hooks failed", dart2js never
                                  started, on both

Exact paths asserted:
  build/web/assets/packages/data_asset_gate_package/data/id1.txt
  build/web/assets/packages/data_asset_gate_package/data/generated.txt

Reading of the failure cases: a failed build leaves the previous build/web
output on disk, so a present asset file is not evidence of success. The gate
judges the failure cases by exit code and by the absence of "dart2js: Starting"
in the verbose log.

Gate runs (commands)
--------------------
  FLUTTER=.research/flutter-sdk/bin/flutter         PUB_CACHE=<writable> \
    tooling/data_asset_gate/run.sh        -> PASS (exit 0)
  FLUTTER=.research/flutter-sdk-patched/bin/flutter PUB_CACHE=<writable> \
    tooling/data_asset_gate/run.sh        -> PASS (exit 0)

The gate reports exit 7 when the data-asset feature flag is off, so a silent
"asset missing" cannot be confused with "feature disabled".

What this answers
-----------------
The dependency-hook `DataAsset` path is PRESERVED by the ordering patch: the
hook runs first, the declared asset and the hook-generated asset both land in
build/web with matching content, incremental builds skip the hook, changed
inputs propagate, and both a missing input and a throwing hook fail the build
before the compiler starts.

Limits
------
- App-root hooks are not covered here. Flutter's own
  dev/integration_tests/data_asset_app covers that shape upstream.
- Data assets require the `enable-dart-data-assets` feature flag on 3.47.x;
  the same behaviour without the flag is "hook runs, nothing bundles", which is
  why the gate checks the flag first.
- Only `flutter build web --release` (dart2js host) was used for this gate. The
  asset pipeline is shared, but dart2wasm was not re-measured here.
- `flutter_tools`' own data-asset integration tests were not re-run in this
  round; the gate is a narrower, DWI-owned reproduction.
- Nothing here says the prototype is accepted upstream. It is evidence that
  ordering hooks before the compiler does not break declared data assets.

Not claimed
-----------
- That any released SDK orders web hooks before the compiler.
- That DWI's supported workflow no longer needs `dart run dwi_builder:dwi build`
  before the first Flutter build of a fresh typed-proxy app.
