Source findings (repo-local SDK, read-only inspection)
  1. `Dart2WebTarget.dependencies` ==
     [WebEntrypointTarget(), GenerateLocalizationsTarget()]
     (flutter_tools/lib/src/build_system/targets/web.dart:143-146).
     `Dart2JSTarget` extends `Dart2WebTarget`; `BuildHooks` is not a dependency.
  2. `LinkHooks.dependencies` includes `BuildHooks(platform: web)` and the
     compile targets as `extraDependencies`
     (targets/native_assets.dart:140-147); the web graph instantiates
     `LinkHooks(platform: HookPlatform.web, extraDependencies: compileTargets)`
     (web.dart:601-605). Hooks therefore feed linking, after compilation.
  3. `BuildHooks` declares a result file as its output (native_assets.dart);
     there is no supported way for a hook to declare a Dart source file that
     the compiler must wait for.

Verdict
  The typed-proxy zero-manual-build gate stays OPEN. No supported Flutter
  mechanism orders a dependency build hook before application compilation
  (candidates re-checked: hook output declared as a compiler input — unsupported;
  app-root hook — not run; dev_dependency hook — not run; committing generated
  proxies — stale by design and rejected by ADR-008 determinism).
  The supported workflow is unchanged: run `dart run dwi_builder:dwi build` (or
  `dwi build --flutter-build`) once before the first Flutter build; afterwards
  ordinary Flutter commands keep the worker fresh. An app that calls `Dwi.run`
  directly and imports no generated proxy builds on the first ordinary command
  (measured 2026-11-04, retained).
  Evidence for this re-measurement: tooling/proxy_gate and this file.

NOT PROBED here
  Flutter release-mode `flutter run`, worker replacement while a page is live
  (separate probe), `flutter build web --wasm` for the proxy fixture, and any
  non-Chrome engine for the runtime check.
