Conclusion
  VERIFIED: hook discovers the app and task, compiles the worker, writes the
  proxy/manifest, packages web/dwi/worker.dart.js into build/web, resolves the
  worker under /sub/app/, runs the task off the UI thread, invalidates on task
  and helper edits, and is skipped when unchanged.
  NOT VERIFIED / BLOCKED: a fresh project cannot rely on the hook alone for
  the first build, because Flutter does not order generated proxies before
  dart2js. The supported workflow is one `dart run dwi_builder:dwi build` (or
  `dwi build --flutter-build`) before the first Flutter build; afterwards the
  hook keeps the worker fresh. Flutter run/hot-reload replacement of a running
  worker was not probed.
