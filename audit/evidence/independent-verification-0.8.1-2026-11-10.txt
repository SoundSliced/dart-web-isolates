Observations outside the verified fixes
  1. `Dwi.close()` does not keep the applied configuration: it sets the cached
     backend to null, and the next call builds a fresh backend without
     `configure`, so it uses the default worker script. Measured: a Wasm-configured
     app that calls `Dwi.run`, then `Dwi.close()`, then `DwiWorker.spawn` requests
     `/dwi/worker.dart.js` (404) instead of `dwi/worker.boot.mjs`. Pre-existing,
     unrelated to these fixes; the probe was restructured to avoid it.
  2. `docs/architecture.md:173` still states that an app-root `hook/build.dart`
     did not run. Measured on 3.47.6: it does run when the app depends on
     `hooks`; it is still not ordered before the compiler. Pre-existing stale
     claim.
